# Рай перекупа · FFXIV · 0.2.1

Настольное приложение на Python с тёмным русским интерфейсом. Ищет дешёвые **целые стаки** на других мирах того же дата-центра, сравнивает с состоявшимися продажами на вашем мире и сообщает о выгодных предложениях в Telegram.

По умолчанию: **покупка на мирах Light → продажа на Shiva**, ходовые товары всех категорий. Мир продажи можно сменить; DC покупки определяется по его принадлежности. Другие дата-центры и регионы при поиске покупки не используются.

## Запуск

Нужен **Python 3.10+ с Tkinter**. В Windows распакуйте ZIP и запустите `start.bat`: при первом запуске создаётся отдельное окружение `.venv` и устанавливаются закреплённые `websocket-client 1.9.2` и `pymongo 4.18.3` (BSON). Глобальная установка Python не меняется. Интернет нужен для первой установки. Для демонстрации с искусственными ценами — `start_demo.bat` (Telegram и обновление данных отключены).

```text
python bootstrap.py
python bootstrap.py --demo
python bootstrap.py --profile C:\FFXIVTools\my-reseller-profile
```

В Linux нужен пакет `python3-tk`, на macOS — Python с работающим Tk. Защищённое сохранение токена предусмотрено для Windows; на других системах снимите галочку сохранения и вводите токен при запуске.

При обычном запуске в фоне проверяется последний стабильный релиз `Dediinside/ffxiv-reseller-paradise` на GitHub. Ошибка проверки не мешает поиску. Новая версия устанавливается вручную из ZIP после закрытия программы. В DEMO автоматическая проверка отключена; проверка версии не обновляет рыночные цены.

## Поиск и мониторинг

1. Выберите мир продажи, качество, категорию и бюджет. Пустой бюджет означает отсутствие лимита.
2. Во вкладке «Расходы и отбор» задайте минимальные прибыль/ROI/скидку, спрос, свежесть цен, налоги и стоимость дороги.
3. Нажмите «Найти выгодные стаки». Каждая строка — отдельное предложение целого стака. Заголовки сортируют числа; повторный щелчок меняет направление. Поиск по названию фильтрует результаты. Двойной щелчок открывает товар на Universalis с миром покупки; отдельная кнопка открывает мир продажи. Доступен CSV.
4. Для повторения нажмите «Начать мониторинг». По умолчанию следующий цикл начинается через пять минут после завершения предыдущего. «Остановить» отменяет будущие циклы и текущую операцию после выхода из сетевого запроса. При закрытии программы или сне компьютера поиск прекращается; после запуска мониторинг включается вручную.

Каталог содержит **16 845 рыночных предметов всех категорий** глобального клиента. Названия EN. Исходные `Item` и `ItemUICategory` взяты из одного commit [xivapi/ffxiv-datamining](https://github.com/xivapi/ffxiv-datamining) — `d71de329cc6ed30c6fb16b9108cdf7d29c653302`, таблицы от 17 сентября 2026. Это извлечённые сообществом данные. Каталог и миры/DC можно обновить отдельными кнопками; при ошибке рабочий снимок сохраняется.

## Как отбираются сделки

### Цена продажи после покупки

Горячие находки остаются в таблице после 90 секунд и события удаления. Статус меняется на «Нужно перепроверить» или «Снято или изменено»; последнее не означает, что товар купили именно вы. Столбцы «Продажа/шт.» и «Продать на» находятся рядом с названием. Выберите строку и нажмите «Копировать цену продажи» для копирования числа без разделителей. Расчёт цены и прибыли относится к моменту находки; перед выставлением откройте рынок продажи и проверьте конкурентов.

Кнопка «История находок» открывает отдельное окно с сохранёнными ценами, мирами, HQ/NQ, количеством и временем находки. История доступна после перезапуска и поиска в другом режиме. Поиск по названию работает по всему архиву, окно показывает последние 500 совпадений. Исходный расчёт не перезаписывается при повторе события. Выделение и подробности в основной таблице сохраняются при обновлениях потока.

История хранится локально в `hot-finds.sqlite3` рядом с настройками, без токена; DEMO использует отдельный `demo-finds.sqlite3`. Сохранённые строки не отправляются повторно в Telegram и не считаются свежими сигналами. Исчезнувшие до установки 0.2.1 строки восстановить из этой истории нельзя: прежняя версия их не сохраняла. Если ранее пришло Telegram-уведомление, рассчитанная цена есть в его тексте.

Есть обычный поиск всего каталога и горячая проверка событий. Экономические ограничения применяются в обоих режимах.

## Горячие предложения

Кнопка **«Горячие предложения»** запускает постоянную подписку WebSocket на добавление/удаление объявлений миров покупки того же DC. Большой предварительный обход каталога не нужен. Проверяются только предметы и конкретные версии стаков, пришедшие в событиях; другие выгодные строки обычного API не превращаются в горячие уведомления. Категория, HQ/NQ, список своих ID и экономические фильтры сохраняются. Параметры фиксируются на запуске потока — после изменения остановите и запустите его заново.

Пометки **«Впервые замечено в потоке»**, **«Цена снизилась»** и **«Изменился стак»** описывают наблюдение программы. Они не доказывают, что предмет только что выставили в игре: игроки передают данные в Universalis позже. При первом наблюдении неизвестного объявления нельзя восстановить предысторию. Повторные и полные повторные списки фильтруются сохранённой историей версий; изменение только времени обзора не является новой находкой. Для отсутствующего/синтетического ID используется семантика предмета, мира, ретейнера, качества, цены, количества и дополнительных признаков; одинаковые стаки могут оставаться неразличимыми, что прямо отмечается.

Поток группирует события короткими пакетами, затем проверяет текущие предложения через REST и историю продаж выбранного мира. История кэшируется отдельно по предмету до 120 секунд без искусственного продления даты. До Telegram конкретный стак и экономика подтверждаются ещё раз. Событие может опередить запись API: выполняются ограниченные повторы до истечения срока кандидата. Отсутствующие/удалённые, просроченные или невыгодные предложения не отправляются.

Очередь ограничена 512 редакциями; возраст кандидата — до 90 секунд. Таблица хранит до 200 свежих находок и удаляет просроченные даже при тихом потоке. Счётчики перегрузки и просрочки видны в статусе. Соединение использует проверку TLS, двоичные BSON-пакеты и переподключение с паузой до 60 секунд. Во время разрыва и при перегрузке события могут быть потеряны; гарантия получения каждого объявления не даётся. Статус различает подключение/отключение и результаты проверки.

**Лимит горячих рекомендаций** действует суммарно между событиями, переподключениями и запусками. Успешно отправленное Telegram-уведомление резервирует стоимость стака и его объём; бюджет учитывает установленный резерв. Это учёт рекомендаций, а не реальных покупок. После проверки своего кошелька/инвентаря остановите поток и нажмите **«Сбросить лимит горячих рекомендаций»** в расходах. Само исчезновение объявления ничего не освобождает. Объём одного товара/HQ ограничен долей спроса совместно для всех миров покупки.

Лимит уведомлений применяется к скользящей минуте, а не к одному событию. Сброс бюджета не сбрасывает этот счётчик. Предложение может обойти обычную паузу по товару, если цена покупки улучшилась относительно последней горячей рекомендации минимум на **25%** (настраивается). Точный повтор отправленного стака подавляется в обоих режимах. HTTP 429 Telegram даёт ограниченный отложенный повтор; неоднозначный тайм-аут доставки автоматически не повторяется, чтобы не рассылать дубликаты. Успешная доставка учитывается до отменяемых пауз, включая нажатие «Остановить».

История увиденных редакций и лимиты находятся рядом с настройками в отдельных SQLite-файлах. Токен туда не записывается. В DEMO этот режим использует искусственные события без WebSocket и Telegram. Первичный протокол: [документация Universalis WebSocket](https://github.com/Universalis-FFXIV/universalis-docs/blob/main/components/WebSocketDocumentation/WebSocketDocumentation.tsx).

## Обычный поиск

**Предварительный отбор:** aggregated API Universalis возвращает минимальную цену DC, среднюю цену фактических продаж и скорость продаж на выбранном мире. Среднее используется только для поиска кандидатов. За цикл по умолчанию обходится 3 000 товаров с чередованием частей каталога; подробно проверяется до 100 кандидатов. Ранее не проверенные кандидаты имеют преимущество при следующей встрече, затем учитывается выгода. Лимиты можно увеличить. Один цикл не равен проверке всего каталога, а предварительный отбор может пропустить сделки при искажённом среднем.

**Подробная проверка:** все объявления DC и до 1 800 продаж за последние семь дней на мире продажи. HQ/NQ анализируются раздельно; манекены исключены. При достижении лимита истории спрос считается нижней границей. «Мой список товаров» принимает ID через запятую и пропускает предварительный отбор по средней цене; ID можно найти по названию во вкладке каталога.

Обычная цена — меньшее из медианы цен отдельных сделок, медианы с весом по проданному количеству и медианы последних суток (если такие продажи есть). Это защищает от дорогих мелких сделок и учитывает недавнее снижение. Предлагаемая цена продажи дополнительно ограничена самым дешёвым предложением на мире продажи минус заданное снижение.

Расход = полный стак + налог покупки (округление вниз на стак) + дорога. Выручка = вся партия по предлагаемой цене минус налог продажи (консервативное округление вверх). Прибыль = выручка − расход. Настраиваемые налоги по умолчанию — 5% / 5%. Неизвестная цена или недоступный API не заменяется нулём.

Проверяется ещё один сценарий: цена продажи падает на **10%** дополнительно. В рекомендации проходят стаки с положительной прибылью в этом сценарии. Процент можно изменить. Таблица показывает обычную прибыль и прибыль «При падении»; это сценарий, не прогноз.

Спрос по умолчанию: ≥3 шт./день, ≥5 сделок за неделю, продажи минимум в трёх разных суточных интервалах и последняя продажа не старше 24 часов. Запас предложений не дороже нашей цены +5% считается близкой конкуренцией. По умолчанию исключается запас свыше семи дней общего спроса.

Модель срока: `близкий запас / общий спрос + размер нашего стака / (общий спрос × наша доля)`. Доля по умолчанию 25%, предельный срок три дня. Она учитывает конкуренцию даже после снижения цены на 1 gil, однако не является точной очередью или гарантией продажи.

## Максимизация прибыли и корзина

Три приоритета: **«Оборот прибыли»** (прибыль при падении цены / модель срока), **«Отдача капитала»** (этот показатель / затраты) и **«Прибыль стака»**. Показатели за день опираются на модель срока; их нельзя считать обещанием доходности.

Зелёным выделяется рекомендуемая корзина. Она выбирает по одному стаку на товар/HQ, соблюдает **суммарный бюджет**, оставляет по умолчанию 20% бюджета резервом и ограничена числом уведомлений за цикл. Простой последовательный выбор по приоритету не доказывает глобальный максимум прибыли. Переключатель позволяет показать только корзину. Остальные строки — альтернативы, покупать всё сразу не предлагается.

Бюджет относится к текущему набору, а не к учёту кошелька. Программа не знает о ваших покупках, инвентаре и уже выставленных товарах: после закупки скорректируйте бюджет и список отслеживания. Связанные риски спроса нескольких товаров и изменение цен после покупки не моделируются. Материя, окраска и индивидуальная ценность предмета не оцениваются — сравнение основано на Item ID и HQ/NQ.

## Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather), команда `/newbot`. Вставьте токен во вкладку **Telegram**, не в чат с помощником.
2. Откройте созданного бота и отправьте `/start`.
3. Нажмите «Найти Chat ID» и явно выберите свой личный чат. Если у бота активен webhook, метод getUpdates недоступен: используйте отдельного бота либо введите известный Chat ID. Для группы также можно ввести её числовой ID вручную.
4. Нажмите «Отправить тест», затем включите «Отправлять найденные предложения», сохраните и начните мониторинг.

Состояния сохраняются в `%LOCALAPPDATA%\FFXIVResellerParadise`, вне папки распаковки. Токен хранится отдельно с **Windows DPAPI для текущего пользователя**; в ZIP, обычном JSON настроек, CSV, текстах ошибок и GitHub его нет. На Windows токен невозможно перенести другому пользователю простым копированием файла.

Уведомляются предложения **корзины**, повторно проверенные через свежий запрос непосредственно перед отправкой. При включённом Telegram уже уведомлённые варианты исключаются до выбора корзины, чтобы новые сделки не блокировались прежними лидерами. В тексте: мир покупки, HQ/NQ, размер стака, стоимость, обычная и предлагаемая цена, прибыль/сценарий падения, спрос и две ссылки Universalis. Повтор одного объявления подавляется 30 дней; новые объявления того же товара/качества/мира — по умолчанию два часа. Chat ID учитывается отдельно. Между сообщениями пауза 1,1 секунды, максимум десять за цикл. Защита от повторов записывается только после подтверждённой доставки.

Если снять «Сохранять токен» и сохранить настройки, прежний защищённый файл удаляется; токен остаётся в памяти до закрытия программы. При усечённой истории, не покрывающей заданное число дней, товар исключается с отдельным пояснением. Это недостаточная глубина истории, а не доказательство отсутствия спроса; можно уменьшить число дней в настройках.

При ошибке Telegram отправка текущего набора прекращается; сообщение не считается доставленным. Автоматического повтора неоднозначного сетевого запроса внутри цикла нет; после тайм-аута доставка могла состояться и повтор в будущем возможен. При ошибке сохранения защиты от повторов окно сообщает об этом. Отправка в реальный чат требует вашего токена и Chat ID; тесты используют подменённый транспорт. [Документация Bot API](https://core.telegram.org/bots/api).

## Свежесть и нагрузка

Цены Universalis обновляются игроками. Свежий HTTP-ответ сам по себе не означает свежий рынок. Проверяется `worldUploadTimes` отдельно для мира покупки и продажи; по умолчанию данные должны быть не старше двух часов. `lastReviewTime` — дата размещения объявления и не используется как время наблюдения. [Исходный формат объявлений](https://github.com/Universalis-FFXIV/Universalis/blob/v2/src/Universalis.Application/Views/V1/ListingView.cs).

Кэш предварительного отбора — пять минут, подробных снимков — две минуты. При ошибке сети старые данные не подставляются. Переключатель «Свежий запрос API» обходит кэш. HTTP-пакеты: до 100 ID для предварительного отбора, до 10 для всех объявлений/истории. Последовательная сеть ограничена десятью запросами в секунду; повторные попытки учитываются, `429` вызывает паузу. Ограничитель относится к этому приложению; другие приложения на вашем IP имеют свою нагрузку. [Лимиты Universalis](https://github.com/Universalis-FFXIV/universalis-docs/blob/main/components/RestWelcome/RestWelcome.tsx).

При пустом результате показываются охват, кандидаты, параметры и причины отсева: свежесть, спрос, прибыль, бюджет, конкуренция или размер стака. Пустая таблица не означает, что весь DC уже проверен.

## Проверка

```text
.venv\Scripts\python -m unittest discover -s tests -v
```

Тесты проверяют экономику, падение цены, бюджет корзины, стабильность спроса, старые/будущие данные, ротацию каталогов, реальные названия, HTTP/429, DPAPI, Telegram без реальных отправок, защиту от повторов и GUI. Подробности — в `VALIDATION.md`.

Приложение не взаимодействует с клиентом игры и не покупает товары. Игровые названия принадлежат Square Enix; источники — xivapi/ffxiv-datamining и Universalis.
